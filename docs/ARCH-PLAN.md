# FRAMZ OS на Arch Linux — план перехода

> Решение основателя (принято): база — **Arch Linux (archiso)**. Приоритеты — **лёгкость + полный
> контроль + стабильность через откат** («откат сделаем — и всё»). Ядро — **чуть изменённое под игры
> и разработку**: скорость, но без потери удобства. Оболочку меняем **по компонентам**, Plasma остаётся движком.

---

## 1. Почему Arch подходит под эти приоритеты

| Наш приоритет | Как Arch отвечает |
|---|---|
| **Лёгкость** | ISO ~1,3 ГБ против 4,3 ГБ; в системе нет ничего «за компанию», ставим ровно то, что нужно |
| **Полный контроль** | свои пакеты, своё ядро, свой загрузчик, свой установщик, любой файл — наш |
| **Стабильность через откат** | Btrfs + снапшоты: перед каждым обновлением точка; в GRUB отдельный пункт «вернуть как было» |
| **Скорость разработки** | пакеты свежие, PKGBUILD — минуты, AUR — тысячи готовых рецептов |
| **Творческая аудитория** | свежие драйверы и Mesa — важно для Krita/Blender/Kdenlive и планшетов |

**Честно о минусе:** Arch обновляется быстро и иногда ломает. Поэтому **откат — не опция, а часть системы**:
Btrfs + `snapper` + `grub-btrfs` + автоснапшот перед каждым обновлением. Человек всегда может вернуться
к состоянию «до», не читая документацию.

---

## 2. Схема системы

```
Флешка (наш ISO, archiso)
   └─ меню: Установить / Запустить без установки / Проверить память
        └─ Live-режим: наш рабочий стол + ярлык «Установить FRAMZ OS»
             └─ Calamares (наше оформление)
                  ├─ разметка: Btrfs (по умолчанию: @ и @home, при желании LUKS)
                  ├─ базовая система: наш список пакетов
                  ├─ загрузчик: GRUB + наша тема + grub-btrfs (откат)
                  └─ завершение: «Готово» + подсказки

Установленная система
   ├─ GRUB (наша тема) → Plymouth (наш знак) → SDDM (наш экран) → Plasma (наш стол)
   ├─ снапшоты: авто перед обновлением, ручной «framz snapshot», откат из GRUB
   └─ ядро: linux-zen + наши настройки (см. раздел 4)
```

## 3. Что переносим из уже сделанного (ничего не пропадает)

| Сделано | Как переезжает на Arch |
|---|---|
| Обои, знак, палитра | PNG/SVG копируются в `airootfs` и в образ как есть |
| Тема оформления `org.framz.desktop` (цвета, splash, defaults) | файлы Plasma переносятся 1:1 |
| Наша раскладка панели (панель, док, знак в кнопке) | переносится 1:1 (Plasma есть на Arch) |
| Иконки Kora | пакет `kora-icon-theme` из AUR или наш PKGBUILD с пином по коммиту |
| Окно первого запуска `framz-welcome` | переносится 1:1 (kdialog есть в Plasma) |
| Оформление установщика Minimal Mono | переиспользуем CSS-цвета/знак в Calamares (другая раскладка, тот же стиль) |
| Скрипты `framz-quickstart.sh`, `framz-vm.sh`, `framz-usb.sh` | переиспользуются, меняется имя файла ISO |
| Творческий набор приложений | тот же (Flatpak), список уже готов |
| Документация | переиспользуется, обновляем названия путей |

## 4. Ядро: игры + разработка (без потери удобства)

**Берём `linux-zen`** (уже собран под отзывчивость: PREEMPT, 1000 Гц) и добавляем своё:

| Что | Зачем | Как |
|---|---|---|
| `CONFIG_SCHED_CLASS_EXT=y` | планировщики нового поколения: `scx_lavd` для игр, `scx_bpfland` для разработки | наш конфиг ядра + пакет `scx-scheds` |
| Профили нагрузки | «игра», «разработка», «музыка/видео» — переключаются в один клик | утилита `framz tune game\|dev\|studio` (под капотом `sched_ext` + `gamemode` + `ananicy-cpp`) |
| `gamemode` | игры получают приоритет автоматически | пакет + включение в Steam/играх одним переключателем |
| `pipewire` с нашим квантом | аудио без задержек для записи и MIDI | `pipewire.conf.d/` с нашими значениями |
| BBR + `zram` (zstd) | сеть и память под нагрузкой | `sysctl.d/` + `zram-generator` |
| `nohz_full` (опция) | меньше «дёрганий» ядра во время рендера | параметр загрузки, включается профилем |
| `irqbalance` + `thermald` | ровная частота, меньше троттлинга | сервисы включены, но с нашими настройками |

**Как это не ломает удобство:** по умолчанию — сбалансированный профиль (всё как у людей), переключение
на «игру/разработку» — по желанию, в окне первого запуска и в трее. Свой конфиг ядра собираем **нашим
PKGBUILD** — обновления ядра приходят от нас, не «сюрпризом» от чужого пакета.

## 5. Откат (то, о чём просил отдельно)

1. **Btrfs** для системы, снапшоты Btrfs — мгновенные, места почти не занимают.
2. **Автоснапшот перед каждым обновлением** (`snapper` + hook `pacman`).
3. **Пункты в GRUB** («FRAMZ OS — откат к …») через `grub-btrfs` — человек выбирает точку при загрузке.
4. **Наша утилита:** `framz snapshot` (сделать точку), `framz rollback` (вернуть), `framz rollback --list`.
5. **Проверка «откат работает»** — в список обязательных тестов перед выпуском (жёсткий тест, раздел 7).

## 6. Сборка ISO

```bash
# локально (Arch или контейнер archlinux)
sudo mkarchiso -v -w /tmp/framz-work -o out framz-arch/
# в CI: тот же самый вызов внутри контейнера archlinux:latest
```

- Профиль лежит в репозитории: `framz-arch/` (см. файлы рядом).
- Наш код и оформление **не дублируются**: сборка копирует `files/system/*` и `iso/branding/*` в `airootfs`.
- Сборка в CI: новый workflow `build-arch.yml` (ручной запуск + метка-файл), результат — `framz-os-arch-1.0.iso`.
- Fedora-сборка остаётся рабочей, пока Arch-версия не догонит по функциям (две ISO рядом — не проблема).

## 7. Жёсткий тест перед выпуском (обязательный список)

| Тест | Что проверяем | Чем |
|---|---|---|
| Загрузка ISO | доходит до рабочего стола | QEMU + снимки экрана (workflow `iso-verify`) |
| Установка | проходит целиком, без ошибок | QEMU, автоматический ответчик + снимки |
| Загрузка после установки | GRUB, Plymouth, SDDM | QEMU |
| **Откат** | снапшот создаётся, откат возвращает систему | скрипт-проверка внутри ВМ |
| Панель и лаунчер | элементы на месте, кнопка запуска с нашим знаком | снимки экрана + проверка конфигов |
| Брендинг | `os-release`, GRUB, Plymouth, SDDM, установщик | `scripts/iso-selfcheck.sh` + снимки |
| Профили ядра | «игра/разработка/студия» переключаются | проверка сервисов и планировщика |
| Приложения | Krita, Blender, Kdenlive, OBS, Ardour запускаются | smoke-тест запуска |

## 8. Порядок перехода (чтобы ничего не потерять)

| Этап | Что делаем | Результат | Силы |
|---|---|---|---|
| 1 | Профиль archiso, наш список пакетов, Live-режим с нашим оформлением | грузится ISO, на нём наш стол | 2–3 дня |
| 2 | Calamares с нашим оформлением, установка на Btrfs | система ставится и грузится | 3–4 дня |
| 3 | Снапшоты и откат из GRUB | работает `framz snapshot` / `rollback` | 2 дня |
| 4 | Своё ядро (PKGBUILD) и профили нагрузки | `framz tune` переключает | 3–5 дней |
| 5 | GRUB-тема, Plymouth, SDDM, звуки | загрузка и вход наши | 1–2 недели |
| 6 | Лаунчер и FRAMZ Настройки | по разбору `docs/INTERFACE.md` | 3–6 недель |

**Итого до «Arch-версия не хуже Fedora-версии»:** ~3–4 недели работы, из них первая рабочая ISO — через 2–3 дня.

## 9. Риски и как их гасим

| Риск | Гашение |
|---|---|
| Обновление ломает систему | автоснапшот + откат из GRUB + предупреждение в окне обновлений |
| Своё ядро отстаёт от обновлений | наш PKGBUILD с автопроверкой новых версий + сборка в CI по расписанию |
| Расхождение документации и reality | в каждом релизе гоняем список тестов из раздела 7 |
| Две базы (Fedora и Arch) путаются у людей | на время перехода у каждой ISO своя страница и имя файла; после этапа 6 — Fedora-сборка уходит в архив |
