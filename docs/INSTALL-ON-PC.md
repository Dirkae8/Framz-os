# Установка FRAMZ OS на компьютер с флешки (в том числе на пустой, без системы)

> Полный тутор от нуля: скачать ISO → записать флешку → настроить BIOS → поставить систему.
> Работает и на машине **вообще без ОС** — единственное, что нужно, это *любой* рабочий компьютер
> (Windows, Mac или Linux), чтобы записать флешку.
>
> ⚠️ **Главное, что надо понять сразу:** установка на внутренний диск **стирает всё**, что на нём было.
> Сначала сохрани важные файлы. Если в компьютере есть Windows, которую жалко — читай раздел
> «Вторая система рядом с Windows» в конце.

---

## Что понадобится

| Что | Требования |
|---|---|
| Флешка | **8 ГБ и больше** (ISO ≈ 4,3 ГБ). Всё на ней будет стёрто |
| Рабочий компьютер | любой, с USB-портом: Windows / macOS / Linux — только чтобы записать флешку |
| Интернет | ~4,3 ГБ трафика на скачивание |
| Компьютер-цель | 4 ГБ ОЗУ минимум (лучше 8+), 25+ ГБ на диске, UEFI (для машин 2012+ это норма) |

Производительность и совместимость, честно:

- **AMD/Intel видеокарты** — работают из коробки, включая аппаратное ускорение видео.
- **NVIDIA** — система загрузится и будет работать на свободном драйвере `nouveau`, но тяжёлые задачи
  (рендер в Blender, CUDA, NVENC) на нём не поедут. Проприетарный драйвер ставится вручную
  (см. «Если у тебя NVIDIA» ниже), а вшитым в образ он появится на этапе 2.
- **Планшеты Wacom/XPPen** — поддержка уже в образе (`libwacom`), проверяем на живом железе.

## Шаг 1. Получить один файл ISO

Скачай файлы релиза со страницы: <https://github.com/Dirkae8/Framz-os/releases/tag/v1.0-preview>

**Какие ISO бывают:** `framz-os-1.0.iso` (базовая), `framz-os-1.0-nvidia.iso` (драйвер NVIDIA
внутри — бери, если у тебя NVIDIA), `framz-os-1.0-studio.iso` (полная: Krita, Blender, Kdenlive,
OBS, Ardour и др. уже внутри). Файлы выложены **частями** (GitHub не принимает файлы больше 2 ГиБ),
число частей зависит от размера ISO.

### На Linux / macOS

```bash
mkdir -p ~/framz && cd ~/framz
BASE=https://github.com/Dirkae8/Framz-os/releases/download/v1.0-preview

curl -fL -C - -O "$BASE/framz-os-1.0.iso.part-aa"
curl -fL -C - -O "$BASE/framz-os-1.0.iso.part-ab"
curl -fL -C - -O "$BASE/framz-os-1.0.iso.part-ac"
curl -fL -C - -O "$BASE/framz-os-1.0.iso-SHA256"
curl -fL -C - -O "$BASE/framz-os-1.0.iso.parts-SHA256"

# собрать один файл
cat framz-os-1.0.iso.part-* > framz-os-1.0.iso

# проверить (Linux)
sha256sum -c framz-os-1.0.iso.parts-SHA256     # части
sha256sum -c framz-os-1.0.iso-SHA256           # собранный ISO → должно быть OK

# проверить (macOS)
shasum -a 256 -c framz-os-1.0.iso-SHA256
```

### На Windows (PowerShell)

```powershell
cd $HOME\Downloads
$BASE = "https://github.com/Dirkae8/Framz-os/releases/download/v1.0-preview"
curl.exe -L -o framz-os-1.0.iso.part-aa "$BASE/framz-os-1.0.iso.part-aa"
curl.exe -L -o framz-os-1.0.iso.part-ab "$BASE/framz-os-1.0.iso.part-ab"
curl.exe -L -o framz-os-1.0.iso.part-ac "$BASE/framz-os-1.0.iso.part-ac"

# склеить части (важен порядок: aa, ab, ac)
cmd /c copy /b framz-os-1.0.iso.part-aa+framz-os-1.0.iso.part-ab+framz-os-1.0.iso.part-ac framz-os-1.0.iso

# проверить сумму
curl.exe -L -o framz-os-1.0.iso-SHA256 "$BASE/framz-os-1.0.iso-SHA256"
Get-FileHash .\framz-os-1.0.iso -Algorithm SHA256 | Format-List
# сверь строку Hash с содержимым файла framz-os-1.0.iso-SHA256
```

Ожидаемый размер: **≈ 4,2 ГиБ**. Если сильно меньше — скачивание не завершилось, повтори (`-C -`
продолжает с места обрыва).

**Если проверка суммы не сходится**, а скачивал ты недавно: возможно, релиз в этот момент
пересобирается на GitHub (автосборка идёт ~25 минут). Подожди и скачай заново.

## Шаг 2. Записать флешку

> ❗ **Нельзя просто скопировать файл ISO на флешку** — она не загрузится. Нужна запись «образом»
> (посекторно). Именно этим занимаются утилиты ниже.
>
> ❗ В BIOS/прошивке Fedora-ISO нужно писать **в режиме DD / «прямая запись»**, а не «ISO-режим».
> В Rufus для этого при появлении вопроса выбрать **«Записать в режиме DD-образа»**.

### Вариант A. Наш скрипт (Linux, самый безопасный)

```bash
# посмотреть, какие диски подключены
~/framz-usb.sh list

# записать (подставь СВОЮ флешку: /dev/sdb, /dev/sdc, ... — но не системный диск!)
~/framz-usb.sh write --device /dev/sdX
```

Скрипт сам проверит контрольную сумму ISO, откажется писать на системный диск, на смонтированную
флешку и на устройство меньше ISO, а потом спросит подтверждение словом `ЗАПИСАТЬ`.
Если скрипта нет — скачай его:

```bash
curl -fsSL -o ~/framz-usb.sh \
  https://raw.githubusercontent.com/Dirkae8/Framz-os/arena/01a0ee0e-framz-os/scripts/framz-usb.sh
chmod +x ~/framz-usb.sh
```

### Вариант B. Вручную из терминала (Linux/macOS)

```bash
lsblk                       # Linux: найти флешку, например /dev/sdb (НЕ /dev/sdb1)
diskutil list               # macOS: найти флешку, например /dev/disk4

# Linux
sudo dd if=~/framz/framz-os-1.0.iso of=/dev/sdX bs=4M status=progress conv=fsync
sudo sync

# macOS (обрати внимание: rdisk — быстрее)
diskutil unmountDisk /dev/disk4
sudo dd if=~/framz/framz-os-1.0.iso of=/dev/rdisk4 bs=4m status=progress
diskutil eject /dev/disk4
```

`of=` — это **флешка целиком** (`/dev/sdb`), а не её раздел (`/dev/sdb1`). Ошибёшься с буквой —
сотрёшь свой диск. Поэтому вариант A со скриптом надёжнее.

### Вариант C. Графические утилиты

| Система | Утилита | Как |
|---|---|---|
| Windows | **Rufus** (rufus.ie) | Выбрать ISO → схема **GPT / UEFI** → при предложении выбрать **DD-режим** → Пуск |
| Windows | **balenaEtcher** (etcher.balan.io) | Flash from file → выбрать ISO → выбрать флешку → Flash. Проще всего |
| Windows | **Fedora Media Writer** | Официальная утилита Fedora: «Custom image» → выбрать наш ISO |
| Linux | **GNOME Disks** | Три точки → «Восстановить образ диска» → выбрать ISO и флешку → Начать |
| Linux | **KDE ISO Image Writer** (`isoimagewriter`) | Выбрать ISO → флешку → Write |
| Linux | **balenaEtcher** (AppImage) | Как в Windows |
| macOS | **balenaEtcher** | Как в Windows |

**Ventoy** тоже подойдёт (просто копируешь ISO как файл на подготовленную флешку), но с установщиками
атомарных Fedora он иногда не находит образ внутри себя. Если загрузка с Ventoy не идёт — пересоздай
флешку Rufus'ом в DD-режиме или через `dd`.

**Важно:** после записи Windows может предлагать «отформатировать диск» — **не соглашайся**,
это нормальное поведение (в системе появились разделы, которые Windows не понимает).
Чтобы вернуть флешку к обычной работе, её потом просто отформатируют в NTFS/exFAT.

## Шаг 3. Настроить BIOS/UEFI и загрузиться с флешки

### Как войти в BIOS или меню загрузки

Включаешь компьютер и **сразу многократно жмёшь** нужную клавишу. Часто нужно зажимать `Fn`
на ноутбуках (например, `Fn+F2`).

| Производитель | Вход в BIOS | Меню загрузки (быстрее всего) |
|---|---|---|
| ASUS (мат. платы, ноутбуки) | `Del` / `F2` | `F8` |
| MSI | `Del` | `F11` |
| Gigabyte / Aorus | `Del` | `F12` |
| ASRock | `F2` / `Del` | `F11` |
| Lenovo ThinkPad | `F1` / `Enter`+`F1` | `F12` |
| Lenovo IdeaPad / Legion | `Fn+F2` | `Fn+F12` |
| Dell / Alienware | `F2` | `F12` |
| HP | `Esc` → `F10` | `F9` |
| Acer | `F2` / `Del` | `F12` |
| Samsung | `F2` | `F10` / `Esc` |
| Toshiba | `F2` | `F12` |

**Самый быстрый путь** — меню загрузки (`F12`/`F11`/`F8`): там просто выбираешь флешку
(её имя обычно содержит «USB», «Kingston», «SanDisk», «UEFI: ...»).

### Что проверить (и что исправить) в BIOS

| Настройка | Значение | Зачем |
|---|---|---|
| **Secure Boot** | **Выключить (Disabled)** | ISO пока не подписан — с включённым Secure Boot система не загрузится, увидишь «Security Violation» |
| Режим загрузки | **UEFI** (не Legacy/CSM) | наша база — UEFI-система |
| **Fast Boot** | Выключить | иначе флешка не увидится при включении |
| **Intel RST / RAID / VMD** | Переключить на **AHCI** | иначе установщик **не увидит твой диск** (частая беда на Dell, HP, Lenovo) |
| Порядок загрузки | поставить USB первым (или просто выбрать через меню) | чтобы загрузиться с флешки |
| (Опционально) VT-x / AMD-V | Включить | пригодится для виртуалок внутри FRAMZ OS |

Не забудь **сохранить и выйти**: обычно `F10` → `Yes`.

### Если флешка не появляется в меню загрузки

1. Проверь, что записал её не «копированием файла», а утилитой (Rufus- DD / Etcher / `dd`).
2. В BIOS включи режим **UEFI** (или, наоборот, попробуй Legacy, если машина очень старая).
3 В некоторых Dell/HP нужен ручной путь: **Boot from file** → `EFI/BOOT/BOOTX64.EFI` на флешке.
4. Перевоткни флешку в другой USB-порт (лучше USB 2.0 сзади на десктопе).
5. Проверь флешку на другом компьютере: если и там не грузится — перезапиши её заново.

## Шаг 4. Установка

1. **Загрузка.** Появится меню загрузчика → выбери верхний пункт (обычно он сам стартует через 10 сек).
2. **Язык и раскладка.** Выбери `Русский` и свою раскладку.
3. **«Установить на жёсткий диск»** (Install to Hard Drive) — ярлык на рабочем столе.
4. **Хранилище (Installation Destination).** Здесь самое важное:
   - выбери **внутренний диск** (SSD/HDD) — не флешку!
   - если диск чистый или не жалко: **«Автоматически»** (Automatic) — установщик сам разметит
     (EFI-раздел + Btrfs-раздел системы).
   - если хочешь **зашифровать диск** («Защитить мои данные паролем»): включи **шифрование**
     (LUKS). Тогда при каждом включении система попросит пароль. **Пароль потеряешь — данные не вернуть.**
   - жми **«Готово»** (Done) и подтверди удаление данных на диске.
5. **Пользователь.** Создай учётку, поставь пароль и обязательно отметь
   **«Сделать администратором»** (Administrator) — иначе не сможешь ставить программы.
6. **Пароль root** — задай (можно такой же, можно другой).
7. **«Начать установку».** Занимает 10–25 минут в зависимости от диска. Можно пить чай.
8. По окончании — **«Перезагрузить»** и **вынь флешку**, когда экран начнёт гаснуть
   (или после перезагрузки, если система уже грузится с диска).

**После перезагрузки** система загрузится с внутреннего диска — это уже установленный FRAMZ OS.
Если снова грузится установщик, значит загрузка идёт с флешки: вынь её и в меню загрузки выбери
внутренний диск.

## Шаг 5. Первые 10 минут в системе: что сделать

Открой терминал (в KDE: `Ctrl+Alt+T` или через меню приложений) и проверь, что всё на месте:

```bash
cat /etc/os-release | head -3        # база Fedora/Kinoite
rpm -q btop distrobox pipewire-jack-audio-connection-kit libwacom argyllcms
flatpak list --app                   # Firefox, Flatseal, Warehouse
rpm-ostree status                    # состояние системы и список откатов
```

Обновить систему до свежего состояния (атомарно, с возможностью отката):

```bash
rpm-ostree upgrade      # скачает и подготовит обновление
systemctl reboot        # применится при перезагрузке
```

Если что-то пошло не так после обновления — **вернуться назад одной командой**:

```bash
rpm-ostree rollback     # вернуться к предыдущему состоянию
systemctl reboot
```

Установить программы (пока магазин FRAMZ не готов — через Flatpak):

```bash
flatpak remote-add --if-not-exists --user flathub https://flathub.org/repo/flathub.flatpakrepo

# пример: творческий старт
flatpak install flathub org.kde.krita org.inkscape.Inkscape org.blender.Blender
flatpak install flathub org.darktable.Darktable org.kde.kdenlive com.obsproject.Studio
flatpak install flathub org.ardour.Ardour org.gimp.GIMP net.scribus.Scribus
```

Или просто открой **Discover** (магазин KDE) — он умеет ставить Flatpak'и из Flathub.

### Если у тебя видеокарта NVIDIA

Система работает на свободном драйвере. Для CUDA/рендера/NVENC можно поставить проприетарный
(это **изменит систему** и потребует перезагрузки; на этапе 2 мы вшиваем это в образ правильным образом):

```bash
# подключить RPM Fusion (nonfree) и поставить драйвер
sudo rpm-ostree install \
  https://mirrors.rpmfusion.org/nonfree/fedora/rpmfusion-nonfree-release-$(rpm -E %fedora).noarch.rpm
sudo rpm-ostree install akmod-nvidia xorg-x11-drv-nvidia-cuda
systemctl reboot
```

⚠️ После обновлений ядра такие «наложенные» пакеты переустанавливаются автоматически, но могут
конфликтовать. Если что-то сломалось — `rpm-ostree rollback` вернёт систему. Для продакшена
на NVIDIA лучше дождаться образа FRAMZ с вшитым драйвером (этап 2).

## Вторая система рядом с Windows (если Windows жалко)

Возможно, но порядок важен:

1. **Windows должна быть установлена первой** (если ставить Windows после Linux, она затрёт загрузчик).
2. В Windows: **отключи BitLocker** (или сохрани ключ восстановления) и **отключи Fast Startup**.
3. Освободи место: «Управление дисками» → сжать том → получи неразмеченное место (лучше 40+ ГБ).
4. Загрузись с флешки FRAMZ OS и в «Хранилище» выбери **«Установить на свободное место»**
   (не «автоматически на весь диск» — иначе сотрёшь Windows).
5. Не удаляй EFI-раздел Windows. Установщик создаст свою загрузочную запись рядом.
6. Порядок загрузки будет в меню UEFI (обычно `F12`). Если после установки пропала запись Windows —
   она восстанавливается через `efibootmgr` или загрузочную флешку Windows.

Если не уверен — лучше поставь FRAMZ OS на **отдельный диск** или в **виртуальную машину**
(см. [`RUN-ON-GARUDA.md`](RUN-ON-GARUDA.md) и [`START-HERE.md`](START-HERE.md)).

## Проблемы и решения

| Симптом | Причина | Что делать |
|---|---|---|
| «Security Violation» / «Verification failed» | Включён Secure Boot | Выключить Secure Boot в BIOS (ISO пока не подписан) |
| Флешки нет в меню загрузки | Fast Boot, режим Legacy, плохой порт | Выключить Fast Boot, включить UEFI, другой USB-порт, перезаписать флешку |
| Установщик **не видит диск** | Intel RST/RAID/VMD включён | BIOS → SATA/Storage → **AHCI** |
| Чёрный экран после выбора «Start Fedora» | Проблема с выводом графики | В меню загрузчика нажми `e`, допиши к строке `linux`: `nomodeset`, `Ctrl+X` |
| Установка падает без объяснений | BIOS/режим диска, либо нехватка места | Проверь AHCI, поставь галочку «Автоматическая разметка», минимум 25 ГБ |
| Система не грузится после установки | Загрузка идёт с флешки или сломан порядок загрузки | Вынь флешку; в BIOS поставь системный диск первым в Boot Order |
| Windows пропала из меню | Установщик переписал порядок UEFI | Выбрать Windows в меню загрузки (`F12`); при необходимости восстановить загрузчик Windows |
| После обновления что-то отвалилось | — | `rpm-ostree rollback` + перезагрузка (вернёт предыдущее состояние) |
| Флешка «испортилась», Windows просит форматирование | Это нормально для записанного ISO | Отформатируй её в exFAT/NTFS, чтобы использовать как обычную |
| Медленно работает всё | Машина ниже требований или HDD вместо SSD | 4 ГБ ОЗУ — минимум, 8+ ГБ комфортно; на HDD система будет медленнее |

## Что ты получишь (и что пока нет)

**Уже работает:** атомарная Fedora Atomic KDE — обновление и откат в одну команду, кодеки
(RPM Fusion), звук без задержек (`pipewire-jack` + `qjackctl`), поддержка планшетов (`libwacom`),
управление цветом (`colord` + `argyllcms` + ICC-профили), шрифты JetBrains Mono и Noto,
контейнеры (`distrobox`/`podman`), утилиты (btop, KDE Connect, ark, filelight, partitionmanager),
Flatpak'и Firefox, Flatseal, Warehouse.

**Пока нет (этапы 2–3 из [`VISION.md`](VISION.md)):** темы FRAMZ, своих панели/дока/лаунчера,
мастера первого запуска и магазина. Внешний вид сейчас — штатный KDE Plasma.

**Не подписано:** поэтому и Secure Boot выключен, и обновления пока без проверки подписи.
Подпись включим к публичной бете — тогда Secure Boot можно будет вернуть.
